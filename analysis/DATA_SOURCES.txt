       md5 = 8c7e7feb95afe5bb43d1612d33007bf3
     Contents: 392 metropolitan + 547 micropolitan statistical areas
       (939 CBSAs), covering 1,916 counties including territories. (The

   DERIVED FILES (deterministic joins of the file above; no modeling):
     data/cbsa_titles_march2020.csv  (fips, cbsa, cbsa_title, pt)
       md5 = cfe9ba3317f31ca67d9dc3e0a49946bc
       County FIPS = FIPS State + FIPS County; pt = metro if the area is a
       Metropolitan Statistical Area, else micro. One row per county.
       Used to rank CBSAs by name (Figures 3-4).
     data/cbsa_march2020.csv  (fips, pt)
       md5 = 5acabee27612efd76809db0e84de542d
       The same, reduced to county -> type. Used for place-type figures.
       Counties in neither list are non-CBSA (rural) and do not appear.

   REBUILD / AUDIT:
     build_cbsa_crosswalks.do rebuilds BOTH CSVs from
     list1_2020_OMB_March2020.xls via the documented transform above. It has
     been verified to reproduce the shipped CSVs exactly (1,916 county rows).
     You do not need to run it to reproduce Update 1; it is for verification.

Everything else in the do-file is computed from these five sources.
No value in this package is hand-entered except the six SE state
populations in section 3 of the do-file, which are transcribed from
source 4 above and match it digit for digit.
WHY THE CBSA-BY-UNITS TABLE IS BUILT, NOT DOWNLOADED

The table that ranks CBSAs by LIHTC units does not exist as a published file,
from HUD or anyone else, and it cannot, because it is specific to this project's
choices: a 2008-2024 window, N_UNITSR as the unit measure, the March 2020
delineation, and territory exclusion. HUD publishes the project-level database;
OMB publishes the county-to-CBSA delineation. The CBSA totals are the join of
the two. That join is the analysis. Sourcing a pre-made total would just be
trusting someone else's undocumented version of the same join.

What CAN and now DOES come from fixed public sources:
  - The units: HUD National LIHTC Database (project-level, public, versioned).
  - The geography: OMB March 2020 delineation, list1_2020.xls (public, fixed,
    shipped unmodified with a checksum).
  - The transform between them: build_cbsa_crosswalks.do, documented and
    verified to reproduce the shipped crosswalks exactly.

So every INPUT is public and verifiable, and the one STEP that is ours (summing
HUD units to OMB CBSAs) is transparent, deterministic, and reproducible from the
shipped script. That is the correct standard for this kind of work: not "download
a black-box total," but "public inputs + a documented, checkable transform."
